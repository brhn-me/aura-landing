Network and cloud folders

Aura reads music and videos straight from a NAS or a cloud drive: a Windows share or NAS (SMB), WebDAV (Nextcloud, ownCloud), SFTP, S3-compatible storage, Google Drive, OneDrive and Dropbox. Files are streamed, never copied in full, and Aura never writes to them. New in 1.5

Add one

  1. Open Library in the sidebar (admins only) and choose Add network folder under Network & cloud folders.
  2. Pick the kind, give it a name and fill in its fields (below) and the folder inside it.
  3. Press Test connection: it lists the top of the folder. For SFTP, compare the fingerprint it shows with the server's own and press Trust this server.
  4. Press Save: the first scan starts. Later scans read only new and changed files.

SMB (Windows, Synology, QNAP, TrueNAS)server, port, user (empty: guest), password, domainshare/Music

Signing in to a cloud drive

  1. Press Sign in with … and open the link Aura shows; sign in and allow access.
  2. The provider sends your browser to an address on 127.0.0.1:53682 or localhost:53682. On any device other than the server that page doesn't load: that's expected. Copy the whole address from the address bar into the dialog and press Finish sign-in.
  3. The token fills in by itself and is kept encrypted.

What to know

  • What is read (tags while scanning, the parts of a song being played) stays in a cache, 5 GB for all sources by default (Administration → Server → Network folder cache).
  • Each source is rescanned on its own schedule (Rescan every, 24 h by default); Rescan runs one now.
  • A source that can't be reached keeps its songs and shows Unreachable; parts already in the cache still play.
  • Docker includes rclone, which Aura uses for this. With the .deb or the binary install rclone 1.63 or newer (sudo apt install rclone).

NFS, or a share mounted on the server

NFS has no built-in source: mount the share on the server (read-only) and add the mounted folder with Add folder like any local one.

sudo apt install nfs-common && sudo mkdir -p /mnt/nas-music
echo 'nas.local:/volume1/music /mnt/nas-music nfs ro,_netdev,nofail 0 0' | sudo tee -a /etc/fstab && sudo mount /mnt/nas-music

Tip In Docker, pass the mount in as a volume (/mnt/nas-music:/nas:ro) and add /nas. Docker can also mount NFS itself with a named volume (driver_opts: type: nfs), no privileges needed.
